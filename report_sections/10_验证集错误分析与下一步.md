# 第10章　验证集错误分析与下一步实验设计

## 10.1 分析目的与证据范围

前一阶段的 `finetune_gpu_02` 在 VOC2012 验证集上取得 56.84% 的最佳 mIoU，但椅子、自行车、沙发和盆栽仍是表现较弱的类别。本节使用该实验第8轮 `best.pth` 对完整验证集重新推理，目的不是继续报告一个相同的总指标，而是区分以下错误：

- 目标整体漏检为背景；
- 相近类别之间的语义混淆；
- 细长结构和边界丢失；
- 预测区域过大导致的假阳性。

分析覆盖全部1449张验证图片，输入尺寸为384×384，预测去除补边后恢复到原始标签尺寸；标签255仍作为忽略区域。结果来自 `error_analysis/finetune_gpu_02/`，不是额外400张无标签测试图的成绩。

## 10.2 完整性与结果一致性

| 检查项 | 结果 |
|---|---:|
| checkpoint轮次 | 第8轮 |
| checkpoint记录的最佳mIoU | 56.8369% |
| 错误分析重新计算的mIoU | 56.8368% |
| 两者差值 | 约0.0002个百分点 |
| 重新计算的像素准确率 | 88.1995% |
| 已分析验证图片 | 1449 |
| `partial_analysis` | `false` |

重新计算结果与训练日志一致。极小差值不足以构成实验结论差异，后续表格统一沿用训练实验报告中的56.84%。

## 10.3 弱类别整体指标

| 类别 | IoU | Precision | Recall | 主要误判类别 | 该误判占真实像素比例 |
|---|---:|---:|---:|---|---:|
| 椅子 | 19.16% | 31.51% | 32.84% | 背景 | 40.88% |
| 自行车 | 30.17% | 37.48% | 60.71% | 背景 | 32.75% |
| 沙发 | 34.06% | 51.54% | 50.11% | 背景 | 33.76% |
| 盆栽 | 35.29% | 56.46% | 48.49% | 背景 | 45.77% |

椅子的precision和recall同时偏低，说明既有漏检，也有其他区域被误判成椅子的假阳性。自行车recall明显高于precision，表示模型在部分图片中能找到自行车，但预测区域和类别边界不够准确。盆栽precision高于recall，模型更偏保守：一旦给出盆栽预测通常相对可信，但大量真实盆栽像素未被识别。四类的最大像素级错误均是背景，说明前景保留能力仍是主要问题之一。

## 10.4 按图片统计的完全漏检

这里的“完全漏检”指某张验证图片中存在该真实类别，但该类别像素召回率为0。统计使用 `sample_class_metrics.csv` 中该类别出现过的全部图片，而不是只统计挑选出的8张最差图片。

| 类别 | 含该类的验证图 | 完全漏检图 | 完全漏检比例 | Recall低于25%的图 | 比例 | 图片级Recall中位数 |
|---|---:|---:|---:|---:|---:|---:|
| 椅子 | 123 | 41 | 33.33% | 76 | 61.79% | 15% |
| 自行车 | 79 | 16 | 20.25% | 25 | 31.65% | 54% |
| 沙发 | 90 | 11 | 12.22% | 30 | 33.33% | 49% |
| 盆栽 | 85 | 39 | 45.88% | 54 | 63.53% | 6% |

盆栽和椅子的图片级漏检最突出：盆栽接近一半的相关图片完全没有正确像素，椅子三分之一完全漏检。自行车的总体recall相对较高，但仍有约五分之一相关图片完全漏检，且precision偏低。因此四类不能采用完全相同的改进解释或只看单一IoU数字。

## 10.5 代表性错误案例

以下图片是按类别recall和IoU排序后选出的最差样本，适合说明失败模式，但不代表该类别所有图片的平均表现。

### 自行车被人物区域吞并

![自行车完全漏检并主要混淆为人物](../error_analysis/finetune_gpu_02/visualizations/bicycle/01_2007_001630.png)

样本 `2007_001630` 中自行车与骑行者高度重叠，真实自行车的细杆和车轮结构没有形成稳定预测，错误主要落入人物类别。这说明问题不仅是类别不平衡，还包括深层低分辨率特征对细长结构的表达不足。

### 椅子与沙发发生语义混淆

![椅子整体被预测为沙发](../error_analysis/finetune_gpu_02/visualizations/chair/01_2008_004612.png)

样本 `2008_004612` 中椅子面积为51592像素，却被整体预测为沙发，其中93.73%的椅子像素落入沙发类别。这是大目标上的类别混淆，不能用“目标太小”单独解释。

### 盆栽细叶和枝条整体消失

![盆栽整体被预测为背景](../error_analysis/finetune_gpu_02/visualizations/pottedplant/01_2011_001863.png)

样本 `2011_001863` 中盆栽面积为58243像素，但预测几乎全部为背景。目标包含大量细叶、枝条和孔隙，直接从深层特征上采样难以恢复这些空间细节。

### 大面积沙发仍可能整体漏检

![沙发在复杂场景中被大面积漏检](../error_analysis/finetune_gpu_02/visualizations/sofa/01_2011_003182.png)

样本 `2011_003182` 的沙发面积达到150302像素，仍有98.06%的沙发像素被判为背景。前景中还有兔子等显著目标，模型更关注局部目标而忽略承载它的大面积沙发。这进一步说明当前瓶颈同时包含上下文和语义判别问题，而非只有输入分辨率不足。

## 10.6 结论与局限

完整错误分析支持以下结论：

1. 当前弱类别的主要问题包含整目标漏检，不能只归因于边缘不平滑。
2. 自行车和盆栽的细长结构明显受损，当前DeepLabV3从深层特征直接上采样的解码方式可能是瓶颈之一。
3. 椅子与沙发存在语义混淆，且大面积沙发也会漏检，因此继续单纯提高输入分辨率不能覆盖全部错误。
4. Dice Loss和骨干后段微调已带来提升，但未消除弱类别的图片级完全漏检。
5. 最差8张图片是有意筛选的失败案例，不能用它们估计总体错误率；总体比例必须使用完整逐图CSV统计。

当前分析仍是单次训练、单个checkpoint和单一验证集上的结果，不能证明某个改进在不同随机种子下必然有效。像素级混淆也不能替代实例级评价：同一图片中多个同类物体会被合并统计。

## 10.7 下一步实验：浅层特征融合解码器

下一步优先实现 MobileNetV3 + DeepLabV3+ 式解码器。新结构保留深层特征和ASPP提供的语义信息，同时引入较高分辨率的浅层特征，通过1×1卷积降维后与上采样的深层特征融合，再生成最终类别预测。目标是同时改善自行车、盆栽的细节恢复和前景保留。

为了避免一次改变过多因素，实验分两阶段：

### 阶段A：只比较解码器

| 项目 | 设置 |
|---|---|
| 实验编号 | `deeplabv3plus_decoder_01` |
| 骨干 | ImageNet预训练MobileNetV3-Large，全部冻结 |
| 输入尺寸 | 384×384 |
| 损失 | CE + Dice，权重保持不变 |
| 优化器与调度 | AdamW + cosine，与 `highres_dice_01` 相同 |
| 训练轮数 | 20 |
| 唯一主要结构变化 | 增加浅层特征投影和融合解码器 |
| 主要对照 | `highres_dice_01`：55.68% |

阶段A先判断浅层融合本身是否有效。新解码器参数随机初始化，不能直接把旧DeepLabV3分类头当作新结构的公平结果。

阶段A现已完成：第20轮最佳验证mIoU达到58.02%，相对公平对照 `highres_dice_01` 的55.68%提高2.34个百分点；21类中19类提升，自行车提高12.52个百分点。结果支持浅层融合有效，完整配置、逐轮结果和逐类对比见 `report_sections/11_DeepLabV3Plus浅层融合实验.md`。

该结构现已完成代码实现。MobileNetV3第3块输出24通道、96×96浅层特征（384输入时，输出步长4），最终块输出960通道、24×24深层特征（输出步长16）。深层特征经过ASPP后上采样到浅层尺度；浅层特征通过1×1卷积投影为48通道，两者拼接后经过两层3×3卷积生成21类预测。新模型约1173万参数，原DeepLabV3-MobileNetV3约1103万参数，增加约70万参数。

GPU冒烟检查命令：

```bash
python train_baseline.py --device cuda --architecture deeplabv3plus --backbone mobilenet_v3_large --freeze-backbone --image-size 384 --batch-size 4 --lr 0.001 --lr-scheduler cosine --min-lr 0.00001 --loss ce_dice --dice-weight 1.0 --epochs 1 --max-train-batches 1 --max-val-batches 1 --no-checkpoints --output-dir experiments/deeplabv3plus_gpu_smoke
```

20轮正式实验命令：

```bash
python train_baseline.py --device cuda --architecture deeplabv3plus --backbone mobilenet_v3_large --freeze-backbone --image-size 384 --batch-size 4 --lr 0.001 --lr-scheduler cosine --min-lr 0.00001 --loss ce_dice --dice-weight 1.0 --epochs 20 --log-every 20 --output-dir experiments/deeplabv3plus_decoder_01
```

本地已用随机初始化模型完成1个训练batch和1张验证图的前向、CE+Dice、反向传播和参数更新检查；该局部检查不代表正式精度。正式实验首次启动时会加载ImageNet预训练MobileNetV3骨干。

### 阶段B：有效后再微调骨干后段

阶段A已经满足进入条件。下一步从阶段A最佳权重开始解冻骨干最后3个模块，使用与 `finetune_gpu_02` 相同的分组学习率和10轮预算，实验编号为 `deeplabv3plus_finetune_01`。阶段B的主要对照更新为阶段A的58.02%；56.84%只保留为旧结构的历史最佳。

阶段B命令预案如下；只有阶段A结果通过后再运行：

```bash
python train_baseline.py --device cuda --architecture deeplabv3plus --backbone mobilenet_v3_large --freeze-backbone --unfreeze-last-blocks 3 --init-from experiments/deeplabv3plus_decoder_01/best.pth --image-size 384 --batch-size 4 --lr 0.0001 --backbone-lr 0.00001 --lr-scheduler cosine --min-lr 0.000001 --loss ce_dice --dice-weight 1.0 --epochs 10 --log-every 20 --output-dir experiments/deeplabv3plus_finetune_01
```

评价时除总体mIoU外，还应重新运行本错误分析，重点比较：

- 椅子、盆栽的完全漏检比例是否下降；
- 自行车precision是否提高，同时保持其recall；
- 椅子与沙发之间的混淆是否缓解；
- 其他17类是否因新解码器出现明显退化。

暂不优先使用强类别权重。椅子和自行车当前precision也很低，直接放大它们的损失可能增加假阳性。也不优先直接改为512×512，因为大面积椅子和沙发仍会整体误判，证据表明分辨率不是唯一瓶颈。若浅层融合后语义混淆仍明显，再开展更强骨干（如ResNet50）的独立对照。

## 10.8 证据文件

- `summary.json`：完整性、checkpoint信息和重新计算的总指标。
- `class_metrics.csv`：21类IoU、precision、recall、F1及主要混淆类别。
- `confusion_counts.csv`：原始像素级混淆矩阵。
- `confusion_row_percent.csv`：按真实类别归一化的混淆矩阵。
- `sample_class_metrics.csv`：每张图片中各真实类别的错误统计。
- `selected_samples.csv`：四个弱类别各8张最差样本及图片路径。
- `visualizations/`：原图、真实标签和预测的三栏对比图。
